# 模拟按键（MioKit.KeySender）

[MioKit](https://github.com/MioKit-Plugins) 插件：把一组键盘按下 / 松开事件保存成可复用节点，再用搜索、热键或其它宿主入口向目标窗口回放。

插件 Id：`com.tinyisle.plugin.key-sender` · 分类：Productivity · 要求 MioKit SDK / 宿主 ≥ 1.3.0

---

## 能做什么

- **录制或手写按键序列**：按真实顺序保存 KeyDown / KeyUp，以及每条事件前的等待时间。
- **回放到原目标窗口**：从搜索结果、触发热键、固定入口等调用；发送前尽量回到调用时的窗口。
- **跨节点保持按键**：例如节点 A 只按下 LeftShift，节点 B 再松开；正常跑完不会偷偷补释放。
- **内置常用动作**：复制（Ctrl+C）、剪切（Ctrl+X）、粘贴（Ctrl+V）——只读、不可删除，可「复制为自定义」再改。
- **分类管理与分享**：用户节点可按分类整理；支持 JSON 导入 / 导出方案。

---

## 快速开始

1. 在 MioKit 中安装本插件并确保 WebView2 可用。
2. 搜索 **「模拟按键管理」**（或打开插件配置窗）进入管理窗口。
3. **新建**节点 → 默认在「录制」页：输入名称后点 **开始录制**，在管理窗前台按下目标键，再点 **停止录制**，已有事件会直接写入草稿。
4. 需要微调间隔、增删事件时切到 **详细** 页；也可使用「插入组合键」快速生成显式 Down/Up 序列。
5. 保存后，在宿主搜索里找到该节点（可设别名、触发热键、固定），对目标窗口执行即可。

内置「复制 / 剪切 / 粘贴」开箱即用；要改序列请先复制为自定义节点。

## 管理窗口

| 区域 | 说明 |
|---|---|
| 顶部 | 搜索、新建、导入、导出、批量删除 |
| 左侧 | 「全部」「系统内置」以及用户自建分类；可新建 / 重命名 / 删除（无系统默认分类） |
| 中间 | 节点列表：名称、描述、内置标记、操作 |
| 右侧 Sheet | **录制** / **详细** 两个标签编辑当前节点 |

其它交互：

- 把节点拖到用户分类可移动；**Ctrl+拖** 为复制。
- 未保存离开会提示保存 / 放弃 / 继续编辑。
- 保存提交点击时的内容；保存期间继续编辑的部分仍显示为未保存，需要再次保存。
- 保存成功后同步节点内存中的序列和等待配置，再次编辑或执行可直接读取新值，无需重启宿主。
- 编辑器中的复制也遵循未保存确认；关闭或切换节点后，旧加载、保存和录制结果不会覆盖新草稿。
- 只有 Down、只有 Up、重复 Down 都可以直接保存；按键配对由使用者配置，不需要二次确认。

在 **宿主入口设置** 中配置触发热键、别名和固定。

---

## 录制与回放

回放顺序固定：

```text
节点前等待 → 第 1 事件前等待 → 第 1 事件 → … → 节点后等待
```

重要行为：

- 录制按每个键的状态变化保存事件；连续重复的 Down 或 Up 只记录一次。停止时立即结束，不等待松键，也不补 KeyUp。
- 回放只发送配置中的事件，**成功、失败、取消、插件停止或卸载都不会自动补发 KeyUp**。
- 不建立跨运行的保持键账本；按下和抬起可以由同一节点或不同节点显式发送。
- 取消只停止所选任务的后续发送；插件停止会取消活动和排队任务。
- 关闭管理窗口直接关闭，不额外改变按键状态；运行中的回放继续执行。
- 录制和回放互斥；需要先结束正在执行或排队的任务，才能开始录制。

「发送成功」只表示系统接受了输入，不等于目标软件一定完成了业务操作。

## 导入 / 导出

- 导出所选节点的已保存定义，以及关联分类的名称、说明和节点归属。热键、别名和固定等入口偏好留在本机。
- 每份文件最多 500 个节点、5 MiB。超过任一限制时请分批导出，原有文件会保留。
- 导入预览显示分类、事件数、等待合计和校验结果。文件和本机各有一个同名分类时复用本机分类，保留本机说明。遇到多个同名分类时，按文件分组新建分类。
- 文件对话框使用 `*.json`。`miokit.key-sender` 文件含分类时使用 v3，无分类时使用 v2。旧 v2 文件可导入为未分类节点。

## 使用提示

1. **录制时保持管理窗口在前台**；失焦会停止录制，并将已有事件写入当前草稿。
2. Esc、F12 等也会被录进序列；停止请用面板上的「停止录制」，不要指望某个键当停止键。
3. 录制写入的事件前等待默认为 **0**；需要间隔请在「详细」里改。
4. 左右 Ctrl / Alt / Shift / Win、主键盘与小键盘 Enter 是不同键，不会自动合并。
5. 内置复制 / 剪切 / 粘贴是 **按键模拟**，不是直接读写剪贴板；结果取决于目标程序。
6. 按键配对、等待间隔和执行效果由使用者配置；插件不自动修正序列或清理按键状态。

## 开发验证

在仓库根目录执行。C# 测试需要 Windows 和 .NET 10；前端建议使用 Node.js 22。

```powershell
dotnet test tests/MioKit.KeySender.Tests.csproj --configuration Release
node --test tests/manager-store.test.mjs tests/key-sender-bridge.test.mjs
pnpm --dir plugin/vue-ui install --frozen-lockfile
pnpm --dir plugin/vue-ui exec playwright install chromium
pnpm --dir plugin/vue-ui test:ui
pnpm --dir plugin/vue-ui build
```

Linux 首次安装浏览器时可使用 `playwright install --with-deps chromium` 安装系统依赖。Playwright 会启动独立的 Vite 服务，并在 Chromium 里操作实际 Vue 页面；数据、录制与文件对话框由浏览器 Mock 提供。C# 测试使用替身验证执行、录制、存储及桥接服务，无需向桌面注入按键。

[测试工作流](.github/workflows/tests.yml) 在推送分支和提交 PR 时运行。宿主真机检查和已知问题见[代码审查与测试覆盖](docs/07-代码审查与测试覆盖.md)。
