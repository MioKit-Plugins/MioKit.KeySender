# 架构与数据模型

状态：本插件**已实现**契约（与 `plugin/` 代码对齐）。存储和运行统一采用事件序列，旧组合键组模型已废弃。实现差异见 [implementation-notes-backend.md](implementation-notes-backend.md)。

## 1. 对象和服务边界

```text
KeySenderPlugin
  └─ KeySenderSearchGroup
       ├─ OpenKeySenderManagerNode
       ├─ KeySenderNode（内置 ×3，仍挂在搜索组）
       └─ KeySenderCategory（用户分类）
            └─ KeySenderNode（用户实例）

节点 → ExecutionService → ConfigurationService / TargetWindowService / NativeKeyboardSender
Vue → KeySenderUiService → ConfigurationService / RecordingService / TransferService / ExecutionService
PluginWebView → KeySenderUiService.OpenSession / OnWindowClosed（会话生命周期）
NativeKeyboardSender → HeldKeyLedger
RecordingService → 自有 Hook 线程
```

管理页侧栏使用虚拟 scope「全部」「系统内置」（`KeySenderConst.ListScopeAll|Builtin|Category`）加上用户 `KeySenderCategory`。删除分类会级联删除其下全部用户节点。启动时 `EnsureCategoriesAndMigrateAsync` 确保固定 Id 的「默认分类」，并把仍挂在搜索组下的旧用户节点迁入该分类。

KeySenderNode 直接继承 MioObject，实现配置 Feature、IInvokeFeature、IAliasNameFeature、IHotkeyFeature、IPinnedFeature、IResultActionProviderFeature、IInvocationPresentationFeature、IRequireTargetWindowFeature。自有 Feature 可用 NodePalette(模拟按键) 分类。

插件根实现 IPluginConfigWindowFeature，管理入口不要求目标窗口。程序集唯一 Register。

搜索组、管理入口与默认分类使用固定带插件前缀的实例 Id。Type/属性 Guid 及首批内置实例 GUID 已在第 10 节固定，直接使用该清单，不重复生成；后续新身份再经 MCP 生成。Guid 集中为 const string + Guid 成对常量。

## 2. 冷热数据

轻量常驻：Name、最长 500 字 Description、AliasNames、触发 Hotkey、固定信息，以及存活节点身份。检查继承后的全部 PreloadPropertySource。

冷字段：

- BeforeDelayMsProperty：EavProperty<int?>，默认 0，整数存储，EavCachePolicy.None。
- AfterDelayMsProperty：同上。
- SequenceProperty：EavProperty<KeyboardSequence>，版本化强类型转换器，长文本存储，EavCachePolicy.None。

不预加载以上详情，不在搜索/列表循环读取，不用 Description 放完整序列，不维护全节点详情 map。列表没有 events、事件数和通过读取详情生成的摘要。

用户节点详情由编辑、运行、复制、导出显式读取一次；使用 GetXxxAsync，不把同步缓存未命中解释为空配置。内置节点走第 10 节的固定定义工厂，在读取边界按需生成，同样不保存完整全局事件数组。返回操作局部对象，结束后释放。

None 的实际 Store 行为必须验证，包括保存后的 dirty 数据。若仍产生干净的长期详情缓存，改用公开 provider 的持久化读取边界且验证不回填存活节点；公共 API 无法满足时报告 SDK 阻塞，不反射清缓存或改宿主字典。

当前录制片段、当前草稿、当前 Run 可以暂时持有事件。账本只保存按键状态，最近记录不保存序列，均不构成全量详情缓存。

## 3. 配置形状

```text
KeyboardSequence
  version: 2
  events: ordered list<KeyboardEvent>

KeyboardEvent
  eventId: string
  type: "keyDown" | "keyUp"
  key: KeyToken
  delayBeforeMs: int = 0

NodeWrite
  name: string
  description: string
  beforeDelayMs: int = 0
  afterDelayMs: int = 0
  sequence: KeyboardSequence
```

eventId 为节点内部行身份，编辑/移动保留，复制事件/节点或导入时重新生成。键可在任意多条事件重复，重复 Down/Up 不按 group 内重复键规则拒绝。

配置只含稳定 token、事件和相对间隔；不存 INPUT/KBDLLHOOKSTRUCT 二进制、CLR 类型名、HWND、扫描码快照、CTS、物理键态或 HeldKeyLedger。

版本、类型、合法 token、eventId 唯一性、上限和等待是硬验证。配对异常是独立分析结果，不能让解码器直接丢弃事件或自动修复。

没有全局发布版本库；首版仅支持 sequence.version=2 和 file formatVersion=2。v1 旧草案明确拒绝。

## 4. 配对分析与确认指纹

纯函数 AnalyzeSequence(write) 以局部 pressed 集合为空开始：

1. Down：若已存在，产生 repeated_keydown 警告；保留事件，集合仍只有一个逻辑按下状态。
2. Up：若不存在，产生 unmatched_keyup 警告；保留事件；若存在则移除。
3. 结束：集合中的键产生 unclosed_keydown 警告，指向最后一次导致保持的事件位置。

这不是引用计数。Down、Down、Up 后该键局部视为释放，不能还要求第二次 Up。

返回硬错误、warnings 和 warningFingerprint。指纹为固定字段顺序的语义 JSON（beforeDelayMs、afterDelayMs、events 的 type/key/delayBeforeMs；不含 eventId、名称和描述）的 UTF-8 SHA-256 小写十六进制。

Create/Update/Copy 提交时重新计算，存在警告且 acknowledgedWarningFingerprint 不匹配则返回 sequence_confirmation_required 和分析结果；匹配后才保存。指纹不作为鉴权，也不需要缓存全部待确认详情。确认信息不存 EAV；再次保存仍需确认当前警告。

执行读取配置时验证硬错误，但不再次弹确认，合法持久配置可能有意不配对。导入用整包警告指纹，见文件篇。

## 5. 插件级持有键账本

HeldKeyLedger 为轻量字典，按 token/规范原生键身份键控：

- key、vk/extended 等目录引用。
- 首次成功提交 Down 的 runId/nodeId 和时间。
- 状态为 held；失败提交可能产生 uncertain，需要释放核实。

所有账本修改由串行输入执行路径完成。成功提交 Down 若已持有，视为重复 Down，不增加计数；Up 成功即移除，无论最初由哪个节点 Down。

节点 B 可以 Up 节点 A 保持的键。Up 在账本无记录时也照用户事件提交，不伪造先前 Down；静态保存分析会提示这一情况。

账本表示本插件已提交的逻辑状态，不宣称精确区分“物理键也同时按下”或其他程序的注入。不主动改写用户物理键状态来对齐账本。

正常 Run 结束不清空账本。活动 Run 取消/失败、手动释放及插件停止会清理全部本插件 held/uncertain 键，不仅是本 Run 新按下的键，并取消后续队列。待执行项取消不影响账本。

账本不能保存完整节点/事件/InvokeContext；已完成 Run 的来源仅是标量。删除保持键来源节点前先经用户确认 ReleaseAll，避免悬空来源。

## 6. 内存所有权与接口

- ConfigurationService：CRUD、分类、验证、确认指纹和配置 gate，不缓存详情。
- ExecutionService：轻量 FIFO、当前配置、取消、有限结果及输入活动预约。
- NativeKeyboardSender：单条 Down/Up 的有限 native 提交；返回 submitted(bool) 和 nativeError，不读 EAV。
- HeldKeyLedger：插件级逻辑状态和释放顺序，不读数据库。
- TargetWindowService：从 context 提取轻量身份，校验和恢复原窗口。
- RecordingService：一个临时事件片段，时间采样与自有 Hook；不录全局历史。
- TransferService：最多一个有期限解析预览；导出写入调用方提供的流（当前实现先收集详情再写包）。
- KeySenderUiService：WebView2 桥接适配（`[JsService("KeySenderUiService")]`）；不实现第二套配置/回放逻辑。
- PluginWebView：单例 Avalonia 窗口；打开时 `OpenSession`，关闭时释放本窗会话/片段/预览/订阅，不销毁全局执行服务与账本。

实际需要的窄边界为配置读写、原生单事件提交、目标窗口和 Hook 事件源；不为每个具体类机械建接口。

执行适配入口应先同步提取 nodeId、来源、TargetIdentity，随后返回异步任务。不要让 async 状态机或委托在排队期间保留整个 InvokeContext、SearchResult、剪贴板图片或 WebView。

## 7. 配置持久化和并发

一把异步配置 gate 协调业务 Save/Delete/Copy/详情冻结/导出读取。不持 gate 等用户确认、等待输入或显示文件对话框。

保存：验证和重新分析 → gate → 核对归属及非内置身份/确认指纹 → 显式属性字典 SaveObjectsAsync → 刷新存活节点轻量缓存 → 新节点完成父关系及发布 → 返回。外部 Update/Delete 对内置实例一律 builtin_read_only；不能只依赖页面禁用。

更新使用真实存活节点保存主表，以显式新属性值提交业务字段，保留其父关系；不能构造 Parent=null 的同 Id 对象覆盖现有主表。提交前不把草稿 Set 到存活节点，不覆盖宿主热键/别名/固定。

新建先以未挂树对象保存主表和属性，再 UpdateParentsAsync 到目标分类（或内置场景下的搜索组），最后 SetParent 发布。父关系步骤与主事务不是同一事务。

主表已提交但父关系/发布失败，明确返回 persisted=true/createdIds；不能让用户盲目重试创建。刷新或启动按业务 MioType、preload:false 找回，幂等修复父关系、加载轻量属性再挂树。

**导入 Commit（当前实现）：** `TransferService.CommitAsync` 对包内节点**顺序**调用 `ConfigurationService.CreateAsync`，不是整包一次 `SaveObjectsAsync`。首个节点失败且未持久化时可保留预览重试；已有节点写入后失败则消费预览并返回 `persisted`/`createdIds`。

批量挂树不是原子操作。新 Id 在轻量 unpublished 集合中，搜索排除、执行返回 node_not_ready；全部完成再统一移除限制。失败摘下本批已挂对象并走恢复。

删除先在 gate 内检查队列/运行及保持键来源。如果需要经用户确认释放，必须离开配置 gate 再调用 ReleaseAll，等清理完毕重新进入 gate，重新验证节点存在、无 Run、无相关保持状态；中间状态变化则返回相应错误，不沿用旧检查。不能持配置 gate 等待活动 Run 退出而死锁。调用 DeleteManyAsync 失败时用 ExistsAsync 核实已删/剩余，返回 delete_incomplete；不假设回滚。核实失败时禁止受影响 Id 新入队，等待重新加载。

锁顺序统一配置 gate → 输入活动短锁；禁止短锁内 await，禁止为等取消而持配置 gate。

## 8. 队列与状态

队列项只保存 runId、nodeId、轻量名称、时间、TargetIdentity、来源和取消控制。容量为 64 等待项，严格 FIFO；取消排队项需立即响应，不等前方长序列。

出队后读取并固定当前配置。排队期间修改生效；运行中再修改仅影响后续运行。Run 局部配置在终态释放，最近 50 条仅保留标量。

状态包括 queued、loading、beforeDelay、waitingExternalKeys、eventDelay、sending、afterDelay、cancelling 和 succeeded/failed/cancelled。held 键不是 Run 的未完成状态：一个 Run 可以成功终结但账本非空。

HeldKeysSnapshot 独立显示 currentKeys、来源、isReleasing、senderAvailable；不能用 Run 完成隐式清空该区域。

ReleaseAll 是串行输入控制操作：关闭提交 → 取消排队/活动 → 等有限 native 提交结束 → 按账本逆序发 Up → 成功恢复提交。它不需要加载任何节点详情。

## 9. 生命周期

启动先准备固定组，按第 10 节幂等确保三个内置实例，再按业务类型恢复其他节点，只加载轻量字段，最后开放搜索和执行；账本从空开始，不从 EAV 恢复“上次按下”。

Run 使用插件绑定 IMioTaskService 及其取消 token，所有排队、延时和 native 后检查能在宿主任务排空阶段退出，不依赖之后 StopCore 才取消。

停止时拒绝新请求，结束录制，取消任务并释放账本，等待 Hook/native/消息线程退出，退订和释放窗口资源。即使没有活动 Run，停止也必须释放较早成功节点留下的 held 键。

若 native Up 清理仍失败，报告失败并保留必要引用/未清理状态，不宣称安全卸载完成。重启时不得重放旧 Down；在允许新输入前确认残留键已释放。

窗口关闭不等于插件停止；普通关闭可按用户选择保持键。窗口会话资源释放不允许顺带销毁全局账本或运行服务。

宿主停止/卸载关闭窗口属于强制生命周期清理，不显示普通关闭的“保持并关闭”确认框，不依赖用户点击才能退出。它直接走停止取消和账本释放路径。

BuiltInKeyCatalog 只保留这三个 Id、名称、说明和主键等小型配方。ConfigurationService 按固定身份判断内置，在 GetDetail/执行/复制/导出读取边界生成独立的 v2 事件序列；事件行 Id 可以每次生成，不是持久化绑定身份。执行器仍消费同一种 KeyboardSequence，不能自己再维护一份复制/剪切/粘贴分支。

内置实例只持久化主表身份、父关系及轻量 Name/Description；不保存 Sequence/等待 EAV，不以它们的缺失当作坏配置。用户节点仍从 None EAV 读取。IsBuiltIn/IsReadOnly 是由固定目录推导的能力，不是可写 EAV，也不接受网页或导入设置。

初始化在配置 gate 内完成：逐个查固定 Id，缺少则创建；已有则校验类型和归属，修复父关系及固定名称/说明。保留宿主别名/热键/固定偏好，不无条件清空，不覆盖用户节点。若同 Id 被其他类型或插件占用，返回 builtin_identity_conflict，禁止覆盖或另造一个随机内置 Id 继续。

插件自身 Update/Delete、批量 Delete、恢复/导入更新路径都检查内置身份。批量请求含任一内置 Id 则整批在副作用前拒绝。用户不能通过改 DTO 的 isBuiltIn=false 或换大小写绕过：ID 在识别目录前按 Guid 规范化，实际存活实例保持固定常量的字符串形式。

复制和导出读取固定定义，复制的新节点是普通随机 Id、有 EAV 详情、可编辑可删除，不能继承只读身份。导出不携带内置 Id 或标记，导入总是用户节点，不能覆盖/冒充内置。

“不可删除”是本插件正常管理和接口的约束，不阻止宿主按用户要求卸载并清理插件数据；外部数据操作导致缺失时，下次启动按原 Id 重建。SDK 没有在本方案中被假定提供通用只读/禁止删除 Feature，也不声称能阻止任意第三方直接操作共享存储。
