# 键盘录入与执行设计

本篇定义自有 Hook 连续录制、逐条回放和跨 Run 持有按键。旧“录入一组后自动结束、回放自动反向释放”的逻辑不再适用。

实现映射：`RecordingService` + `NativeKeyboardHook`、`ExecutionService` + `NativeKeyboardSender`、`HeldKeyLedger`、`OutputHotkeyConflict`。单元测试覆盖语义与 Fake 路径；**真机 Hook/SendInput/焦点验收仍见** [implementation-notes-backend.md](implementation-notes-backend.md)。错误码权威清单：`ValidationCodes.cs`（冲突为 `output_hotkey_conflict`，无 `recursive_trigger`）。

复制、剪切、粘贴内置节点在配置读取边界生成四条固定事件，之后使用本篇同一套队列、窗口校验、发送和清理；不另写直接剪贴板调用或绕过故障处理的专用执行分支。内置动作只读不影响宿主触发/绑定，具体固定 GUID 见架构篇第 10 节。

## 1. 稳定按键目录

持久化大小写敏感 token，不存显示字符串、Avalonia 枚举数值或某库的 SendKeys 表达式。

首版封闭目录：

- KeyA～KeyZ：VK 0x41～0x5A；Digit0～Digit9：0x30～0x39。
- F1～F24：0x70～0x87。
- LeftShift 0xA0、RightShift 0xA1、LeftControl 0xA2、RightControl 0xA3、LeftAlt 0xA4、RightAlt 0xA5、LeftWin 0x5B、RightWin 0x5C。
- Backspace 0x08、Tab 0x09、Enter 0x0D、Escape 0x1B、Space 0x20、CapsLock 0x14。
- PageUp 0x21、PageDown 0x22、End 0x23、Home 0x24、ArrowLeft 0x25、ArrowUp 0x26、ArrowRight 0x27、ArrowDown 0x28、Insert 0x2D、Delete 0x2E。
- PrintScreen 0x2C、ScrollLock 0x91、Pause 0x13、NumLock 0x90、ContextMenu 0x5D。
- Numpad0～Numpad9：0x60～0x69；NumpadMultiply 0x6A、NumpadAdd 0x6B、NumpadSeparator 0x6C、NumpadSubtract 0x6D、NumpadDecimal 0x6E、NumpadDivide 0x6F。
- NumpadEnter：VK_RETURN，扫描码 0x1C，extended=true，与 Enter 区分。
- Semicolon 0xBA、Equal 0xBB、Comma 0xBC、Minus 0xBD、Period 0xBE、Slash 0xBF、Backquote 0xC0、BracketLeft 0xDB、Backslash 0xDC、BracketRight 0xDD、Quote 0xDE、IntlBackslash 0xE2。
- BrowserBack、BrowserForward、BrowserRefresh、BrowserStop、BrowserSearch、BrowserFavorites、BrowserHome：按序 0xA6～0xAC。
- VolumeMute 0xAD、VolumeDown 0xAE、VolumeUp 0xAF、MediaNextTrack 0xB0、MediaPreviousTrack 0xB1、MediaStop 0xB2、MediaPlayPause 0xB3。
- LaunchMail 0xB4、LaunchMediaPlayer 0xB5、LaunchApp1 0xB6、LaunchApp2 0xB7。

首版目录覆盖字母、数字、功能键、左右修饰键、导航键、小键盘与常用媒体/浏览器键等稳定 token。安全注意序列 Ctrl+Alt+Delete 触发时返回硬错误 unsupported_key_combination；分析须按连续事件状态轨迹检查，不能仅检查某一行。

左右 Shift 用扫描码；泛型 Ctrl/Alt 用 extended；Enter 用 extended 区分小键盘。Hook 回调先于异步键态更新，不在回调中调用 GetAsyncKeyState 猜当前事件的左右键。

小键盘 NumLock 关闭时，以非 extended 扫描码识别物理小键盘数字/位置，不混同主导航键。CapsLock、NumLock、输入法和键盘布局不由插件自动切换。

发送 extended=true 的集合：RightControl、RightAlt、LeftWin、RightWin、ContextMenu、PageUp/PageDown/End/Home/Arrow*、Insert、Delete、NumpadDivide、NumpadEnter、NumLock、PrintScreen，以及所有 Browser/Volume/Media/Launch token。其余为 false；Pause 单独按 VK_PAUSE 验证，不把 E1 前缀错当 E0。

存储含义是 Windows 虚拟键及位置，不是 Unicode 文本，也不承诺跨布局的同样文字输出。

## 2. 原始事件与时间

RawKeyboardEvent 包含 vkCode、scanCode、extended、isKeyUp、isSystemKey、injected、lowerIntegrityInjected、timestamp、extraInfo。

录制映射为 KeyboardEvent：

- type：keyDown 或 keyUp，包括 WM_SYSKEYDOWN/UP。
- key：解析后的稳定 token。
- eventId：新 Guid 行身份。
- delayBeforeMs：前一录入事件到本事件的相对毫秒。

同一物理键按住期间的自动重复 KeyDown 只保留第一次；其后重复 Down 消费但不入片段。Up 顺序原样保留，不能改成 Down 顺序的逆序。交错序列如 A Down、B Down、A Up、B Up 完全合法。录制写入的 delayBeforeMs 一律为 0。

记录回调到达时的 Stopwatch 单调时间，不用墙上时钟。以第一条时间为零，累计 elapsed 向下取整到 ms，再用相邻累计值之差得到间隔，避免逐项舍入累积漂移。第一条始终 0。停止时不把“最后事件到点击停止”的时长猜作额外 Up；尾部停顿由节点后等待表达。

录制间隔保存的是观测时序。Hook 调度、回放焦点和系统响应都有开销；不宣称硬实时或逐帧重现。

## 3. 自有 Hook 生命周期

NativeKeyboardHook 使用 WH_KEYBOARD_LL，在专用后台线程初始化消息队列、安装并运行消息循环。持有回调委托直到卸钩及线程退出。

nCode<0 无条件 CallNextHookEx。未消费事件、非当前窗口事件和所有 injected 事件继续链传递。录制期间消费的真实键返回非零，鼠标不处理。

回调只解码、更新小型片段状态并投递通知，不打数据库、不等待 Bridge/UI、不执行文件 I/O、不持长锁。片段以受限列表积累，达到 10000 条请求自动停止。

安装成功才返回 preparing。失败返回 recording_unavailable。卸钩后仍可能存在回调，先等回调/线程退出再释放委托，不在回调线程 Join 自己。

停止经线程消息完成；卸钩失败不能销毁仍被 native 调用的对象或继续装第二个 Hook。报告 recording_cleanup_failed，保持必要引用。

Hook 只在录制及有限排空期间安装，不为了保持输出键持续记录全局键盘。Windows 可能移除超时 Hook；不能仅凭非零句柄宣称它健康。

## 4. 连续录制状态

录制绑定 recordingId、windowSessionId。只允许一个会话，窗口拥有前台时才收集。开始前原子检查：没有 queued/active Run、没有 HeldKey、发送器未处于故障状态。

状态：

- preparing：安装及等待 baseline 键松开。
- recording：连续记录 Down/Up，全部键松开也不停。
- draining：停止/取消后的有限配对排空。
- review：Hook 已释放，片段可应用。
- cancelled：片段丢弃。
- failed：安装或 native 清理等不可继续错误。

开始采样 baseline 在回调以外完成；原先按住的键不作为片段内容，不拦截它们的释放。最多等 2000 ms，超时提示先松键。

recording 维护 physicalDownIdentities 和 ownedSuppressedIdentities。原生身份至少含 VK、扫描码、extended，不能只靠解析后的 token 排空未知键。

- Down/Up 按序加入列表；重复 Down 保留。
- 事件被抑制后记录对应原生所有权。
- 收到合法配对 Up 后移除物理/抑制跟踪，但录制继续。
- 片段可有多轮同键操作，可只有 Up 或只有 Down。
- 不把 Esc/F12 等普通键作为停止键；用窗口内鼠标“停止录制”。
- 不支持的键使录制停止，并给出明确 notice；保留之前合法事件供用户审阅，不能静默跳过后继续声称完整。

主动 Stop 在 Hook 线程处理该命令的边界冻结列表。之后排空看到的 Up **不追加**，这是允许有意保存 Down-only 的必要行为。

失焦相当于 Stop 并附 recording_interrupted notice；Cancel/窗口关闭丢弃片段。录制外不采集，不将别的应用输入持续积累进列表。

## 5. 排空和应用片段

停止或取消后不再消费新独立按键，仅排空本会话先前抑制过的键之重复 Down 和配对 Up。未拥有的 Up 正常传递。排空最多 2000 ms。

超时卸钩；若片段已冻结则以 review + recording_release_timeout notice 提供审阅，不为补齐而自动追加 Up，也不因缺失 Up 直接拒绝保存。native 卸钩失败则 failed，不能 Apply。

不为用户物理键盲目注入“释放全键盘”。录制时没有发送 Down，本阶段的物理排空与 HeldKeyLedger 完全不同。

Apply 只接受 review、Hook 已退出且片段非空。返回显式事件，前端始终全量替换草稿；不会直接创建/更新 EAV。取消幂等，停止重复调用返回同一 review 结果。

review 占用会话直到应用/取消；期间不能提交 Run。片段最多一份，丢弃后释放全部列表和回调引用。

## 6. 保存校验与运行校验

静态配对以空集开始，生成 unclosed_keydown、unmatched_keyup、repeated_keydown 警告。不能把警告当解析失败；用户按指纹确认后可以保存。

未知类型、未知 token、非法时间、重复 eventId、版本错误及超限是硬错误。安全注意组合按事件状态轨迹检查，包括后来叠加修饰键形成的情况。

运行时还要用当前 HeldKeyLedger 初始集预演整段：先前节点持有的 Ctrl 加本节点 Alt/Delete 也必须被安全组合校验和宿主热键冲突检测识别。运行不再显示保存确认。

输出模型不使用 HotKeyInfo；冲突比较时才把左右修饰键规范化到宿主通用键集合。每条 Down/Up 后的实际逻辑键集都检查 Registered 登记，包括重复 Down，不构造超过 7 键的 HotKeyInfo。

运行前整段预检，每条发送前按最新登记再次检查。遇 output_hotkey_conflict 停止并清理；不关闭/清空全局热键注册。ReleaseAll 清理本身不被此预检阻挡。

自有 Hook 仍处于 Windows 链，不能保证先于其他 Hook 或阻止所有系统组合。外部程序登记不一定可枚举，不能声称独占桌面或完全避免所有自触发。

## 7. Run 提交和执行

提交检查节点归属/已发布、录制预约、队列容量；只提取轻量请求。丢失目标的请求在入队前报 target_missing，不改变现有 held 状态。

严格 FIFO，最多 64 项等待。每项有独立完成 Task 和取消源，取消等待项立即完成，不等前方长延时。Run 使用插件绑定 IMioTaskService，所有后台 drain Task 被观察。

出队执行：

1. 读取当前配置、硬校验，用当前账本预演安全组合及已知热键冲突。
2. 等节点 beforeDelayMs。
3. 执行一次外部键准备检查（规则见下一节）。
4. 对每条事件：等待 delayBeforeMs → 校验并恢复原目标 → 重查当前状态下的安全/热键冲突 → 检查取消 → 单条 native 提交 → 成功后更新账本。
5. 等节点 afterDelayMs。
6. 标记 succeeded，释放局部配置，保留账本中尚未 Up 的键，进入下一 Run。

**不能在事件之间等待全部键释放，也不能节点正常结束时自动补 Up。** Down 与 Up 之间的事件延时允许持续持有。

事件等待是相对前一事件提交返回后计时；系统准备额外耗时不会通过压缩等待来“追赶”。迟到不丢事件、不重排。不自动重复失败事件。

取消发生在 native 调用前则不提交；调用已开始则等待有限同步调用返回并处理账本，再响应取消，不能强杀线程。

## 8. 外部键准备与目标

准备只在每个 Run 进入事件序列前执行一次，最多 2000 ms，采样间隔 10 ms。读取异步键态时：

- 已在本插件账本中的键允许继续按下，这是跨 Run 的上下文。
- 本序列在首个 Down 之前显式 Up 的键，允许保持按下后由这些 Up 释放。
- 其他当前按下的键先等待松开，减少触发热键或用户键串入。
- 不等待鼠标按钮，不自动发 Up“修复”用户物理键。

异步键态不能识别所有注入来源，账本也无法辨认用户恰好物理按下相同键的竞争；这只是准备策略，不宣称输入隔离。不要把账本键错误当作必须松开的外部键。

TargetIdentity 从入口 snapshot 取 HWND、PID、可取的启动时间、类名及捕获时间，不保存完整 snapshot。每条发送前核实身份，避免明显句柄复用；不重新捕获当前前台窗口替代。

最小化可请求恢复，再尝试 SetForegroundWindow，最多 500 ms 确认原 HWND 是前台；失败 target_focus_failed。不得用模拟 Alt、AttachThreadInput 或 PostMessage 静默兜底。

目标严格是最初顶层窗口，不跟随新模态、同进程另一窗口或 Alt+Tab。最后校验与 SendInput 之间仍有焦点竞态，不能承诺指定 HWND 投递。

清理 Up 不要求原窗口仍可用，否则原窗口关闭会使释放永远无法完成。

## 9. 单事件提交与账本

每条配置对应一次 SendInput(1)：keyDown 不带 KEYUP，keyUp 带 KEYUP。使用目录虚拟键、位置扫描码和 extended，私有 extraInfo 标记用于诊断。不切换到文本或库表达式模式。

虚拟键模式不设置 SCANCODE/UNICODE。NumpadEnter 使用 0x1C 和 extended；VK-only 的媒体/浏览器键允许 wScan=0。位置键映射失败明确报错。

使用单事件 native 调用是为了精确核对 0/1 提交结果及保留任意事件间隔，不把整串“自动 Down/Up”一次生成。调用返回 1 才正常更新账本：

- Down：新增 held；已 held 时保持一项，不计引用数。
- Up：移除 held；原来不存在也照样提交。
- 返回 0：本事件失败，进入清理，不自动重放。
- 异常导致提交结果不确定：该事件若为 Down，加入 uncertain，进入清理；Up 不确认成功则不移除原 held。

发送成功只表示进入系统输入流。更新账本是已提交逻辑，不代表目标实际处理；跨 Run 账本不能被当作物理状态测量。

## 10. 清理及故障封闭

活动 Run 一旦失败或收到取消：

1. 停止后续事件和节点后等待。
2. 取消全部待执行项，因为其预期持有状态已经失效。
3. 对账本全部 held/uncertain 键按首次保持顺序逆序提交 Up，包括前一成功 Run 留下的键。
4. 全部提交成功则清空账本，给活动 Run 发布失败/取消终态，恢复接收。
5. 清理某 Up 失败，允许一次额外 Up 重试；仍失败则保留该状态，senderAvailable=false，拒绝新 Run。

只取消未出队项不执行清理。普通 Create/Save 失败与录制失败也不擅自释放较早 Run 的保持键；它们不是活动回放失败。

手动 ReleaseAll 和插件停止使用同一串行控制流程：关闭新提交、取消队列/活动、等待活动 native 退出、释放账本；不读取任何节点详情。故障封闭后可再次 ReleaseAll 重试剩余 Up，全部成功才重新开放。

正常成功不进入此清理流程。即使序列只有一个 Down，也不会在 finally 自动释放；finally 只释放任务/内存资源。这是实现最容易违背的产品规则。

只对账本/当前 uncertain 键清理，不向全部键盘发送 Up，不伪造外部物理键所有权。输出键与真实用户输入可能竞争，这个边界必须保留。

## 11. 记录与验收证据

日志包含 runId、nodeId、事件位置、提交 0/1、阶段、等待、native 错误和清理结果；不默认写完整录制内容。最近历史不保留异常链或序列。

录制/回放/保持/清理分别记录生命周期。界面必须能区分“成功结束且仍保持 Ctrl”和“已全部释放”。

重点集成证据：单 Down 成功后键仍 held；另一节点 Up 能释放；长延时中取消会释放先前键；只有 held、没有活动 Run 时卸载也释放；手动 ReleaseAll 在清理失败后仍可重试。
