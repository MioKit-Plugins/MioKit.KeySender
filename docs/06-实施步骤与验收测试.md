## 1. 阶段 0：确认当前事件模型

输入：本套当前文档、公开 SDK/模板、实际宿主。

先确认本版本是显式 Down/Up 事件，不是旧组合键组。不可把序列转换为自动配对的组合键后执行。

通过 MioKit MCP 检查 webview2 开发环境，核对 .NET 10、Runtime、pnpm 和可还原的 1.3.0 配套包。核对 SaveObjectsAsync、UpdateParentsAsync、None 缓存、触发热键注册和任务停止顺序。

输出实际 API 映射和版本记录。公共 API 不足时报告具体阻塞，不用私有反射、空实现或本地宿主 DLL 代替。

## 2. 阶段 1：模板和配置

用 MioKit MCP create_plugin 的 miokit-plugin-webview2 模板，工程 MioKit.KeySender、中文名模拟按键、Id com.tinyisle.plugin.key-sender、作者 tinyisle。

保留现有 docs。模板拒绝非空目录时生成到工作区内临时空目录后审核合并，不能 force 覆盖文档，不复制其他插件骨架。

实现唯一注册器、根/搜索组/管理入口/KeySenderNode 和轻量宿主入口。直接采用架构篇第 10 节已经生成的 10 个固定 GUID，不能为这些身份重新调用生成器；实现复制/剪切/粘贴内置目录、按需定义工厂及启动幂等恢复。

先实现 event schema v2、统一硬验证、配对分析和确认指纹，再实现 None 详情读取、显式保存和父关系恢复。

完成标准：冷字段在启动/列表不加载；Down-only/Up-only/重复 Down 是可确认警告，不是硬错误；保存不自动补 Up。三个内置实例定义只读、不可删、固定身份，共用业务类型和执行器，复制后才成为用户节点。

## 3. 阶段 2：回放、账本和清理

先完成 token 目录及 native 单事件边界，用 fake sender/clock/target 验证序列，再接 SendInput(1)。

实现 HeldKeyLedger、跨节点 Up、重复 Down 非引用计数、FIFO、出队读取配置、事件前等待和原目标校验。

将正常结束和异常清理写成不同路径，不能在 finally 统一释放。清理为插件级语义，会释放较早成功节点留下的键并取消后续队列。

实现 ReleaseAll，即使无 Run、窗口刚打开、sender 故障封闭也可请求重试。停止清理不能再向已经关闭的宿主管理任务入口登记新任务。

完成标准：单 Down 成功后保留；另一节点 Up 释放；活动取消、失败、释放全部、停止均正确收束。

## 4. 阶段 3：连续录制

自有 WH_KEYBOARD_LL、专用消息线程、原始事件映射、单调时钟及上限。

使用事件轨迹先测完整收集；真实录制不以全部键释放自动结束，自动重复 Down 去重为一次，不把释放顺序改为逆序；录制间隔默认全 0。

Stop 冻结片段，排空物理 Up 不追加；失焦保留审阅，Cancel 丢弃。支持只有 Down 的片段，经确认保存。

完成标准：一轮可录多段键盘动作及间隔；Esc 是普通可录键；Hook 生命周期、窗口所有权和全局共存实际验证。

## 5. 阶段 4：WebView2 与桥接

实现分类侧栏、节点表格、Sheet 编辑（录制/详细 Tabs）、逐事件编辑、批量间隔、组合键插入助手、连续录制片段预览及全量替换。

实现保存/复制/导入的指纹确认、ReleaseAll 入口和关闭窗口三选项。**HeldKeys/Runs 面板可不展示**（后端 API + 关窗三选一 + 录制阻挡对话框即可验收 T69 的行为语义）。

实现内置标记、只读详情、复制为自定义、能力字段和混合批量删除阻止；后端不得依赖页面禁用来保护。宿主入口偏好仍按原协议可设置。

Bridge 不直接暴露 native 句柄、服务或任意文件路径。事件实时通知只传轻量状态，不每个输入推送累计完整片段。

完成标准：实际 WebView2 验证 DTO、乱序、主题、关闭和断桥；浏览器 mock 仅算布局验证。

## 6. 阶段 5：迁移文件

实现 v2 文件、严格解析、有界读取、单份预览、整包警告确认、哈希复核、按节点创建与发布恢复。

导出写入用户选择路径；当前实现可先聚合本次导出的写模型再序列化。导入不运行键盘、不带保持状态或宿主绑定。

完成标准：本文 JSON 示例可导入，经确认可保存 Down-only/Up-only；旧 v1 拒绝；硬错误包不提交；部分创建失败须返回 persisted/createdIds 且消费预览。

## 7. 阶段 6：真实验证和发布

运行相关核心测试、C# 构建、pnpm build，确认 ui/dist 发布产物。使用实际宿主验证搜索、热键、固定、别名、轮盘/手势节点绑定、录制、回放、保持与清理。

通过 MCP validate_plugin_json、pack_plugin（显式 PackageVersion）、inspect_plugin_nupkg(expectWebView2=true)。不发布远端。包必须含根 DLL/清单/ui/dist，不含 node_modules、前端源码或宿主共享 DLL。

交付工程、测试摘要、宿主验证记录、已验包 nupkg 和实现差异。没有通过真实验证的能力不标为完成。

## 8. 事件和确认验收

- **T01**：单个 Down 事件是合法结构，分析为 unclosed_keydown，未确认不保存，确认后原样保存。
- **T02**：单个 Up 分析为 unmatched_keyup，确认后可保存。
- **T03**：Down、Down、Up 保留三条，产生 repeated_keydown 警告，最终局部为空，不要求两个 Up。
- **T04**：A Down、B Down、A Up、B Up 保留交错顺序，不自动反向配对。
- **T05**：Ctrl Down、等待、C Down、C Up、Ctrl Up 的时间及内容往返不变。
- **T06**：左右修饰键、主/小键盘 Enter 不合并。
- **T07**：未知类型、未知 key、空序列、重复 eventId、超10000事件及旧版本为硬错误。
- **T08**：名称、描述、NUL、负数/小数/溢出时间统一验证，不能静默钳制。
- **T09**：安全注意组合按状态轨迹检测，包括先 Down Delete 再追加修饰键。
- **T10**：修改事件或时间后旧确认指纹失效；eventId/名称不影响语义指纹。
- **T11**：保存的确认不自动生成 Up，不持久化 token，也不取消编辑区警告。
- **T12**：组合键助手生成显式事件，之后可改 Up 顺序或删除 Up，存储没有另一套组模型。
- **T13**：复制未配对节点也需确认，不能绕过验证。
- **T14**：普通保存确认只认可当前内容，不影响执行时动态热键/持有状态检查。

## 9. 配置、缓存和持久化

- **T16**：搜索、列表、翻页、拖放不读取 Sequence，不生成完整序列摘要。
- **T17**：逐个打开200个详情后，仅当前草稿可达，None 的干净详情不留在 Store。
- **T18**：保存 dirty 数据提交后可释放，验证读/写两条路径，不只验证属性声明。
- **T19**：已完成任务、日志、错误、事件订阅和历史不持有序列。
- **T20**：排队只保存轻量信息，不能因 async context 留住剪贴板图片或详情。
- **T21**：新建保存失败不挂树；成功后重启仍有正确父关系。
- **T22**：更新失败不泄露草稿，成功后轻量缓存与数据库一致。
- **T23**：更新不覆盖宿主刚改的热键、别名和固定状态。
- **T24**：复制重新生成节点/event Id，清空入口偏好。
- **T25**：主事务成功、父关系/挂树失败能按类型恢复；未发布节点不能执行。

## 10. 回放和持有键

- **T27**：四条 Ctrl+C 原样提交，只有显式 Up 才释放。
- **T28**：节点前200、事件前0/50/30/20、节点后300，配置等待合计600 ms。
- **T29**：正常结束 Down-only 后 ledger 非空，不在 finally 自动释放。
- **T30**：另一节点 Up 成功释放前一 Run 的键，不要求相同 nodeId。
- **T31**：同键重复 Down 不计引用数，一个 Up 即移除账本。
- **T32**：账本空的 Up 仍提交，不自动先生成 Down。
- **T33**：Down、500ms、Up 在等待期间维持按下，不在事件间等待全部键松开。
- **T34**：跨 Run 保持键不被误当外部键等到超时；前导 Up 可明确释放。
- **T35**：其他触发键仍按住则准备等待，2000ms可取消超时，不主动释放物理键。
- **T36**：FIFO完整串行，队列64上限；等待项取消立即退出且不清空现有 held。
- **T37**：排队时改配置，出队读新值；活动中改配置不改变本次。
- **T38**：前等待、事件等待、后等待可取消；活动取消释放全部 held 并取消后续项。
- **T39**：活动失败会释放此前成功 Run 留下的键，不只当前新 Down。
- **T40**：SendInput(1) 返回0或结果不确定时停止，不重放 Down，保守清理。
- **T41**：Up提交失败不删账本；清理一次重试仍失败则封闭发送器。
- **T42**：封闭后 UI 可再次 ReleaseAll 重试，成功才开放新 Run。
- **T43**：ReleaseAll 无活动 Run 时仍释放保持键，不需要查 EAV。
- **T44**：连续多个重复/交错事件原样保留，不因时间为0合并掉事件。
- **T45**：native调用开始后取消，等待该有限调用结束并记账后清理，不强杀线程。

- **T48**：交错释放顺序原样保留，不能归约成组合键组。
- **T49**：第一条时间为0，累计单调时间转相邻差，无逐项舍入漂移。
- **T50**：录制期间 Esc/F12可进入片段，鼠标Stop结束，不占普通键作控制键。
- **T51**：Stop时只记录 Down，随后排空 Up 不追加；片段可经确认保存为 Down-only。
- **T52**：baseline原已按键不录入、不截断其原有Up，超时可退出。

- **T54**：失焦Stop保留review，Cancel/关闭丢弃，native兜底不依赖网页请求。
- **T55**：排空只消费自己抑制过的配对事件，超时不注入全键盘Up。
- **T56**：Hook安装失败、卸载失败、线程/委托生命周期有结果，不重复装钩泄漏。
- **T57**：有Run或held时拒绝录制；录制/review预约时不能开始回放。
- **T58**：达到10000条停止并通知，不静默截断；未知键停止并保留明确审阅notice。

## 16. 文档和协议检查

### 内置节点验收

- **T93**：首次安装恰有复制、剪切、粘贴三个内置实例，Id 为固定清单值，共享 KeySenderNodeTypeId。
- **T94**：重复启动/初始化不新增副本，不改变已绑入口、热键、别名和固定状态。
- **T95**：内置名称、描述、事件和全部等待只读；三个序列分别模拟 Ctrl+C/X/V，所有配置等待为 0。
- **T96**：直接调用 Update/Delete 内置 Id 返回 builtin_read_only，没有 ReleaseAll、写库或删除副作用；伪造 DTO 标志和 Id 大小写不能绕过。
- **T97**：混合内置与用户节点的批量删除整批拒绝，不先删除用户项。
- **T98**：复制内置创建普通随机 Id 和新的事件 Id，清空入口偏好，允许修改和删除。
- **T99**：内置导出不含固定身份/只读标记；重新导入只能创建普通用户节点，不能覆盖内置。
- **T100**：内置缺失时按原 Id 重建；固定 Id 类型/归属冲突明确失败，不能覆盖或随机换 Id。
- **T101**：内置按需生成事件，不为所有用户节点加载冷字段；builtin 缺少 Sequence EAV 不被误报坏配置。
- **T102**：10 个固定 GUID 均合法、唯一，类型/属性/实例没有混用，工程值与文档完全一致。
- **T103**：搜索结果、节点面板、轮盘/手势绑定及三种内置执行使用统一协调器；没有直接剪贴板旁路或复制三套执行逻辑。

### 一致性

所有本地链接可解析，JSON合法；事件schema、版本2、警告码、状态和字段在各文档一致。不得保留“每组自动反向释放”“正常结束finally补Up”“录制只一组”等旧设计作为有效要求。

内存验收使用查询计数/解码计数、堆引用和WeakReference，不以工作集短暂不下降直接判泄漏。

最终报告哪些测试真的跑过、哪些需要真实宿主/硬件仍未跑。只有文档和fake测试不能宣称原生录制、跨节点保持或卸载释放已经可靠。
