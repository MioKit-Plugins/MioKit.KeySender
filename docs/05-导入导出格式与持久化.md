# 导入导出格式与持久化

分享文件保存显式事件与间隔，不保存当前键盘状态。正常执行后保持按下属于运行行为，不通过导入文件直接作用系统。解析与写入以 `TransferPackageParser` / `TransferService` 为准。

## 1. 当前格式 v2

逻辑格式 `format: miokit.key-sender`，`formatVersion: 2`。物理扩展名推荐 `.miokeys`；**当前管理窗文件对话框过滤 `*.json`**（建议导出名 `keysender-export.json`），内容格式相同。UTF-8 JSON，读入允许 BOM，输出无 BOM。单个/批量共用结构：

```json
{
  "format": "miokit.key-sender",
  "formatVersion": 2,
  "nodes": [
    {
      "name": "复制",
      "description": "按录制间隔发送 Ctrl+C",
      "beforeDelayMs": 200,
      "afterDelayMs": 300,
      "sequence": {
        "version": 2,
        "events": [
          { "type": "keyDown", "key": "LeftControl", "delayBeforeMs": 0 },
          { "type": "keyDown", "key": "KeyC", "delayBeforeMs": 50 },
          { "type": "keyUp", "key": "KeyC", "delayBeforeMs": 30 },
          { "type": "keyUp", "key": "LeftControl", "delayBeforeMs": 20 }
        ]
      }
    },
    {
      "name": "保持左 Shift",
      "description": "正常结束后继续按住，后续显式释放",
      "beforeDelayMs": 0,
      "afterDelayMs": 0,
      "sequence": {
        "version": 2,
        "events": [
          { "type": "keyDown", "key": "LeftShift", "delayBeforeMs": 0 }
        ]
      }
    },
    {
      "name": "释放左 Shift",
      "description": "可释放另一个节点留下的键",
      "beforeDelayMs": 0,
      "afterDelayMs": 0,
      "sequence": {
        "version": 2,
        "events": [
          { "type": "keyUp", "key": "LeftShift", "delayBeforeMs": 0 }
        ]
      }
    }
  ]
}
```

第一项等待合计 600 ms，事件配对正常；第二项有 unclosed_keydown；第三项有 unmatched_keyup。这两个警告都可以确认后导入，不能当非法包拒绝。

## 2. 验证

根 format 固定 miokit.key-sender，formatVersion 必须整数 2，nodes 为 1～500 项数组。文件 ≤5 MiB，深度≤16，拒绝重复 JSON 属性名、未知字段及 NUL。

每节点：

- name 必填，Trim 后 1～100 UTF-16 code unit。
- description 可省略默认空，最多 500。
- beforeDelayMs、afterDelayMs 可省略默认 0。
- sequence 必填，version=2，events 为 1～10000 项数组。
- 每事件 type/key 必填；type 只接受 keyDown/keyUp；key 为大小写敏感目录 token。
- delayBeforeMs 可省略默认 0；时间必须 0～2147483647 的 JSON 整数，不接受 null、小数、指数、字符串或布尔。

相同 key、多次相同 type、未配对不算格式错误，交给警告分析。重复属性名是 JSON 对象字段重复，不是禁止数组中出现重复 Down。

导入格式没有 eventId；各事件创建新的内部行 Id。禁止传 nodeId、eventId、MioType、ParentId、HotKeyInfo 或 native 结构。未知版本明确 unsupported_format_version/unsupported_sequence_version；旧组模型 v1 不迁移、不猜测。

所有等待累加用 checked Int64；单节点最多 10002 项等待，其上限仍小于 JavaScript 安全整数，DTO 传 JSON 整数。回放不将等待汇总替代具体事件顺序。

## 3. 导出范围

包括名称、描述、节点前后等待、sequence.version、事件顺序、type/key/delayBeforeMs。

仅导出动作定义本身。节点与事件身份、别名、触发热键、固定、最近使用、Run/录制记录、HeldKeyLedger、原目标 HWND 和确认 token 留在本机。Down-only 节点照实导出，不附加 Up。

内置节点允许导出，通过固定定义工厂读取同样的 v2 事件，不导出内置 GUID、isBuiltIn/isReadOnly 或权限字段。导入这种文件得到普通可编辑用户节点，同名不代表同一内置身份。文件携带这些不支持的字段仍按白名单规则拒绝，不能借导入覆盖内置配置。

导出不要求当前保持键为空；只是读取已保存定义，不改变输入状态。当前草稿/片段未保存的内容不导出。

导出先保存对话框（取消不读取全套详情）。确认路径后逐节点 `GetDetailAsync` 收集 `NodeWrite`，再由 `TransferPackageParser.WritePackage` 写入用户选择的流。**当前实现会在内存中保留本次导出的全部节点写模型**，不是“只保留当前节点详情的临时文件原子替换”理想路径；超过上限或任一节点硬错误则失败，不写残缺包。只处理用户明确选择的本插件节点，失效项不能静默漏掉。

## 4. 导入预览与警告

文件框由窗口拥有，录制未结束不打开。选择后有界读取、计算 SHA-256、严格解析、规范化默认值，再进行硬验证和静态配对分析。

根破损、过大或版本不支持直接失败；逐节点硬错误可显示在预览中，canImport=false。只有可确认警告时 canImport=true，但必须确认 warningFingerprint 才能 Commit。

预览逐项仅返回名称、描述、eventCount、totalDelayMs、errors、warnings。完整规范事件只留 C# 一份，释放原始字节和大 JSON 字符串。预览不是新的全部节点详情缓存。

整包 warningFingerprint：固定顺序序列化 nodes 的语义配置数组（各项采用架构篇的事件/时间 canonical 结构，不含身份/名称/描述），取 UTF-8 SHA-256。包内节点顺序改变会使指纹改变。无警告可返回 null。

确认文案明确列出“保持左 Shift”的未释放和“释放左 Shift”的跨节点 Up 等行为，提供“返回修改文件 / 确认警告并创建 N 个副本”。确认不添加事件，不让运行立即发生。

每窗口一份 previewId，TTL 5 分钟。新预览、取消、关闭或过期释放所有模型。对话框返回时窗口已关闭则丢弃，不能把结果交给新窗口。

## 5. Commit 与持久化

1. 验证 windowSessionId、previewId、期限和硬验证状态。
2. 重新有界读取源路径（或重验字节）并比较文件哈希；变化、缺失、不可读都不能提交旧缓存。
3. 有警告时验证整包 acknowledgedWarningFingerprint；缺失/不匹配返回 sequence_confirmation_required，不写数据。
4. **按节点顺序**调用 `ConfigurationService.CreateAsync`（每节点内部：新 Id、SaveObjectsAsync、挂到目标分类/默认分类、发布）。不带触发热键/固定/别名。单节点有警告时使用该节点分析指纹作为 ack。
5. 全部节点成功才返回 createdItems 并释放预览。导入不发送任何输入、不恢复保持键。

创建的全部对象必须为普通用户实例，不使用任何固定内置 Id，不从内容/名称识别“复制”后升级成内置。插件初始化确保内置的过程与文件导入完全分开。

提交开始前可以取消；已开始创建后须等待实际结果。不能告诉用户取消成功后继续后台创建。

**与“整包单次 SaveObjectsAsync”设计差：** 当前不是跨节点单一数据库事务。若尚无节点持久化即失败，可保留预览重试；若部分节点已创建后失败，则消费预览并返回 persistence_failed（或创建错误码），details 含 persisted=true/createdIds，禁止重复建副本。单节点内主表成功但父关系/发布失败的语义仍由 `ConfigurationService.CreateAsync` 处理。

刷新/启动按业务 MioType 的 preload:false 查询恢复未发布节点。数据库主事务、父关系更新、树发布不宣称一个跨系统事务。

重复导入同一文件可以创建另一套副本；同名不合并。成功 Commit 或“已部分/全部持久化但后续失败”的 previewId 只消费一次，并发双击不得重复创建。

## 6. 保存后的确认和回放

导入保存的是用户已经确认的定义，不持久化确认指纹。运行硬校验通过后直接回放，不再弹保存确认；当前持有键和宿主热键状态由运行时独立检查。

Hold-only 与 Up-only 可以来自不同节点，导入时不要求分析整个包的执行顺序，也不把两项合成一项。静态 warnings 以单节点空集基线产生，用户仍可确认有意跨节点衔接。

输出文件版本只描述定义，不保证任意目标软件兼容，不自动下载依赖或执行代码。

## 7. 宿主数据与内存

使用 SaveObjectsAsync 的主表及显式属性字典，不以一串 Set 返回当整体成功。详情 EAV None 且不预加载；保存临时对象在提交完成后释放。

更新节点只提交业务字段和 Name/Description，不覆盖本机入口偏好。新对象 Parent=null 主事务后再公开 UpdateParentsAsync，不能写非公开 Parent setter。

批量删除不能假设事务回滚；失败核实已删和剩余。删除保持键来源前的 ReleaseAll 必须在配置 gate 外执行，等待完成后重新进 gate 校验，不能持 gate 等活动 Run 退出而死锁。

文件错误、确认错误和普通编辑失败不改变当前保持键；只有实际回放失败/取消或明确释放/停止操作才清理账本。
