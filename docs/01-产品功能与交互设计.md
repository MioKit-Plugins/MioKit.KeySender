# 产品功能与交互设计

状态：事件序列首版实施规格（管理页与后台已按本篇落地；宿主真机见 implementation-notes）。参见 [数据模型](02-架构与数据模型.md) 与 [桥接契约](04-WebView2界面与桥接契约.md)。

## 1. 用户模型

一个节点保存一串明确的键盘事件。用户可以录制、逐条编辑、插入或删除事件，再从宿主入口回放。

例如“按住 Shift 选择内容”：

```text
LeftShift Down → 等待 50 ms → ArrowRight Down
→ 等待 30 ms → ArrowRight Up → 等待 20 ms → LeftShift Up
```

也允许两个独立节点：节点 A 只有 LeftShift Down，节点 B 只有 LeftShift Up。A 成功后 Shift 保持按下，B 可以释放。

## 2. 管理窗口

使用宿主风格单例窗口，默认 1080×720，最小 820×560。

- 顶部：搜索、新建、导入、导出和批量删除。
- 左侧：`CategorySidebar` — 虚拟 scope「全部」「系统内置」，以及用户 `KeySenderCategory`（可新建/重命名/删除；默认分类不可删）。删除分类会级联删除其下用户节点。
- 主体：分页节点表格（选择、名称、描述、热键显示、内置标记、操作）；不读取完整事件来生成摘要。热键列仅展示宿主 `hotkeyDisplay`，管理页不录制/编辑触发热键。
- 新建/编辑：右侧 Sheet。默认「录制」Tab（名称、描述、录制）；「详细」Tab 含前后等待与事件表。
- 拖放：节点可拖到用户分类移动（MIME `application/x-keysender-node`）；Ctrl+拖为复制。
- 任务列表与保持键账本不在管理页展示；仍由后端维护。录制被挡住时提供一次性「释放全部并开始」。关窗若有保持键，由 Avalonia 对话框提供「释放并关闭 / 保持并关闭 / 返回」。

搜索只用已加载名称、描述和别名，且限定在当前 scope。按名称 OrdinalIgnoreCase 再按 Id 排序。列表默认 20/页，最多 100。翻页/换条件清空本页批量选择。

内置节点显示“内置 · 只读”标记。首版固定为复制 Ctrl+C、剪切 Ctrl+X、粘贴 Ctrl+V；这是按键模拟，不是直接读取/改写剪贴板，结果由目标软件处理。

选择内置节点时可以查看事件和等待，但名称、描述、所有事件、录制/插入按钮和前后等待都只读；不显示保存、删除操作，显示“复制为自定义节点”。宿主触发热键、别名、固定和入口绑定不属于动作定义，仍通过宿主设置。

内置节点可选中导出，批量选择混入内置节点时禁用批量删除并显示原因，不能悄悄只删除其他项。后端同样拒绝这种请求。

## 3. 草稿与节点操作

新建为前后等待 0、事件为空的 Vue 草稿，未保存前无持久节点。空序列不能保存。

打开详情时才请求冷字段。用请求 generation 防止旧响应覆盖新选择。一个窗口只保留一个详情，取消/切换/关闭后释放完整事件，不缓存全部节点。

保存先做硬校验，再做事件配对分析。硬错误阻止保存；警告按第 6 节二次确认后可以保存。失败保留草稿，不静默补事件。

未保存离开显示“保存并继续 / 放弃修改 / 继续编辑”。保存未完成禁止重复提交。

复制读取源节点的已保存内容，创建新节点与 eventId，名称加“ 副本”（截断保证≤100）；清空别名、触发热键、固定及最近状态。有配对警告时复制也必须经确认，不自动继承用户在另一次操作中点过的按钮。

删除先显示影响，说明外部入口绑定可能失效。有未结束 Run 的源节点禁止删除。删除一个曾产生保持键但当前无 Run 的节点，先提示将取消全部任务并释放仍按下的模拟键，再由用户确认；释放成功后才删除，避免源节点消失但键继续保持。不默默留下不可追溯的保持状态。

上述编辑/删除规则仅适用于用户节点。内置节点必须先通过身份预检，修改或删除返回 builtin_read_only，不进行释放、写库或部分删除等副作用。复制内置节点产生普通用户节点，之后可任意编辑或删除。

批量删除预检任一失败则不开始。底层失败核实实际已删和剩余项，不假设 SDK 自动回滚，按实际结果刷新列表。

## 4. 事件列表编辑

每行包含：序号、事件类型、按键、事件前等待、上移/下移、复制、删除和拖动柄。类型只有 KeyDown、KeyUp。

- 类型和 key 必须明确，不按文本猜测。
- delayBeforeMs 是相对上一事件的等待；第一条的等待在节点前等待之后执行。
- 拖动时事件及其前等待一起移动；eventId 不变。
- 复制产生新 eventId，其余内容相同，允许重复 Down/Up。
- 删除后不自动平衡、合并或排序其余事件。
- 多选批量设置事件前等待，以便将录制间隔统一改为某值。
- 提供“插入事件”和“插入组合键”。组合键助手收集有序键，生成全部 Down 后反向 Up 的显式事件；生成后可任意编辑，不单独保存一个组对象。

按键选择区分左右 Ctrl/Alt/Shift/Win 和主/小键盘 Enter。键目录见第 03 篇。事件上下文中重复出现同一键合法，不能沿用旧“组内键去重”的保存规则。

## 5. 连续录制

录制面向完整片段，是多数用户的主录入路径。

1. 点击“开始录制”；原草稿保持不动直到应用。
2. 若有 Run 或本插件保持键，拒绝开始并提供「释放全部并开始」。
3. Hook 就绪，等待原先按住的触发键释放，再进入 recording。
4. 记录真实 KeyDown / KeyUp；同一物理键按住产生的自动重复 Down 只保留第一次；保留交错按键。
5. 使用管理窗口内鼠标点击“停止录制”。不保留 Esc/F12 等普通键作为停止键，Esc 本身也可被录入。
6. 停止瞬间冻结片段，之后为了排空被拦截的物理键而观察到的 Up 不追加到片段；因此可以得到只有 Down 的片段。
7. 审阅后仅「应用 / 丢弃」；应用始终全量替换草稿事件，不提供追加。

录制时只在管理窗口拥有前台时接收和抑制键盘事件。

窗口失焦时自动停止并保留已录片段，提示“录制因失焦停止”；主动取消/关闭窗口则丢弃片段。用户需在候选有效时自行应用。窗口 C# 生命周期兜底，不依赖网页成功发出最后一个请求。

录制写入的所有事件 `delayBeforeMs` 默认为 0；需要间隔时在「详细」Tab 手工调整。组合键助手生成事件的等待默认也都为 0。

达到 10000 条时自动停止并明确提示，不能静默截断后仍显示“完整录制”。排空最多 2000 ms，不能因用户保持物理键而一直禁止结束。

## 6. 保存警告与确认

分析以“序列局部开始时没有键按下”为静态基线，不猜测下一次运行的全局状态：

- unclosed_keydown：结束时仍有 Down 未被 Up 消去。
- unmatched_keyup：Up 在本序列内没有对应 Down，可能是有意释放其他节点的保持键。
- repeated_keydown：同一个键已在本序列按下时又 Down（手工编辑或导入仍可能出现；录制已去重自动重复）。

这些是提示，**确认后都允许保存**。未知键、非法时间、重复 eventId、空序列、未知事件类型、无效版本和超限仍是硬错误。

确认弹窗列出具体键和事件位置，例如：“左 Ctrl 在序列结束后仍将保持按下。正常结束不会自动释放；取消、失败或点击‘释放全部’时会清理。仍然保存？”

提供“返回修改 / 仍然保存”。只确认当前事件和时间内容；修改内容后旧确认失效。确认指纹为语义校验机制，不是权限凭证。详细握手见桥接篇。

不自动插入 KeyUp，不用确认弹窗偷偷修改事件。保存后编辑区继续显示警告标记，执行时不再弹阻塞确认。导入预览和复制也采用同一警告规则。

## 7. 等待语义

执行顺序固定：

节点前等待 → 第 1 事件前等待 → 第 1 事件 → 第 2 事件前等待 → 第 2 事件 → … → 节点后等待。

例如节点前等待 200，四条事件前等待为 0、50、30、20，节点后等待 300，则配置等待总计 600 ms，不含排队、准备、焦点验证及 native 调用开销。

Down 到相应 Up 之间的等待就是按住时长。正常结束未 Up 的键在节点后等待期间及之后仍保持，不在后等待结束时自动释放。

0 表示没有配置等待，不表示系统绝对零延迟。录制默认全部为 0，可在详细事件表手工修改，不声称回放是硬实时或精确重现所有软件行为。

## 8. 运行、保持状态和释放

运行阶段状态由后端 `RunSnapshot` 维护（排队、读取配置、节点前等待、等待触发键释放、事件前等待、发送第 N 条、节点后等待、完成/取消/失败）。**首版管理页不渲染 Runs 面板**；宿主通知与最近记录仍按轻量规则工作。

所有 Run 串行；跨 Run 可以延续持有键。只有成功提交的 Down/Up 更新插件级账本。正在按下不是节点 EAV 配置，也不写入导出文件。

“释放全部”是明确的操作：停止接受新的 Run、取消全部排队与活动 Run、等活动 native 调用退出、发送本插件账本中键的 Up，成功后清空账本并恢复接收。管理页入口为录制阻挡对话框与关窗三选一（桥接 `ReleaseHeldKeysAsync`）；不依赖隐藏面板。

活动运行取消/失败会释放全部本插件保持键，包括较早成功节点留下的键，同时取消后续排队项，避免它们基于已经失效的按键上下文继续执行。取消尚未出队的单项只移除该项，不释放其他 Run 的键。

插件停止/卸载执行同样的释放流程。普通管理窗口关闭不释放键，也不取消正常 Run；本插件保持状态随插件继续存在。窗口关闭确认若仍有保持键，提供“释放并关闭 / 保持并关闭 / 返回”，不强制替用户选择。

释放失败时封闭发送器，取消后续队列并显示失败，不假装清理成功；允许再次点击“释放全部”重试 Up，不重放任何 Down。

## 9. 宿主入口和焦点

搜索结果 OwnerObject 为真实节点。触发热键通过宿主 HotKeyAction 编辑，不使用事件录制器保存 HotKeyInfo。

**当前搜索附加操作（代码）：**

| 节点 | 已实现 | 占位（抛 `NotSupportedException`） |
|---|---|---|
| 用户节点 | 复制、删除、固定、别名、热键 | 编辑 |
| 内置节点 | 复制为自定义、固定、别名、热键 | 查看、导出 |

搜索路径复制若源序列有警告，会自动带上 `acknowledgedWarningFingerprint` 再提交（无法弹管理页确认框）。打开管理窗请用管理入口节点或插件配置窗。

产品目标仍是：用户节点提供编辑/复制/删除；内置提供查看/复制为自定义/导出。同一个固定实例可同时被多个入口绑定；重启和升级不改变身份，不创建新的副本替换它。

节点声明执行前结束入口交互和需要目标窗口。每条事件发送前确认/尝试恢复入口原目标，无法恢复则停止并清理。原目标策略不自动跟随 Alt+Tab 或模态窗口；这个限制与能表达任意键事件是两回事。

拖放使用公开 MIOKIT-DRAG/1 协议，绑定存活节点，不分享详情。管理页面不提供接受任意 HWND 的“向当前草稿立即发送”功能。

宿主错误通知每个 Run 最多一条；成功无桌面弹窗。最近 50 条仅保留轻量状态，不保存事件内容。

## 10. 导入导出

导出已保存配置，用户取消文件对话框为正常退出。导出不包含尚未应用录制片段和草稿。

导入先校验并预览：名称、事件数、配置等待总计、硬错误和配对警告。硬错误阻止整包；只有警告时提供明确“确认这些警告并创建副本”。未确认不能提交。

导入不执行事件，不带入当前保持键，不修改触发热键。成功后只创建独立节点，详情按需读取。

## 11. 反馈与无障碍

时间框固定 ms 后缀，非整数和超限即时提示。手动选键、行排序和批量间隔都有可键盘操作的替代入口。状态有文字，不仅靠颜色。

空库展示创建/导入入口；详情错误保留列表并允许删除坏配置；保存失败保留草稿；取消请求显示“正在取消”直到实际清理结束。

常见文案包括“序列有未释放按键，请确认”“录制片段已停止，尚未应用”“当前保持：左 Ctrl”“已停止后续任务并释放保持键”。不能把“保存成功”“回放完成”“全部按键已释放”混为一件事。
